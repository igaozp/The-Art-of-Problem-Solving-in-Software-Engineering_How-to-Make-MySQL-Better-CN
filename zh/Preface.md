# 前言

## 本书适合谁？

软件工程师在面对复杂问题时，往往陷入矛盾、难以入手。要走出僵局，不妨把难题当作高回报的机会：真正困难的问题，往往也最能带来洞见与突破。

基于约 20 年的排障经验可以认为：服务器端软件里的多数难题，都可以通过系统的逻辑分析加以解决。MySQL 虽应用广泛，却同样存在大量棘手问题。在分析和改进这些问题的过程中，作者逐步形成了一些独特判断，并由此萌生了写作本书的想法。

本书以 MySQL 中的真实难题为案例，讨论问题分析与解决方法。读者可通过实例与讨论，加深对逻辑推理、数据结构、算法等基础能力的理解。

本书涵盖以下主题：

1. **MySQL 中的逻辑推理**：用逻辑方法分析复杂 MySQL 问题。
2. **计算机科学基础**：与 MySQL 密切相关的计算机基础知识。
3. **MySQL 内部原理**：MySQL 核心组件的入门介绍。
4. **性能测试**：如何科学地测试 MySQL 性能。
5. **MySQL 8.0 的改进**：相对 MySQL 5.7 的关键变化。
6. **单机 MySQL 的改进**：独立实例上的进一步优化。
7. **组复制的进展**：MySQL 组复制方面的重要增强。
8. **从库回放的改进**：从库回放路径上的优化。
9. **性能优化方法**：面向应用的 MySQL 性能优化策略。

**本书的重点：**

围绕提升 MySQL 可扩展性，本书讨论多种优化路径：提高吞吐量、降低响应时间，并尽量让从库性能贴近主库，从而在多数场景下实现延迟很低的高可用切换。

**目标读者：**

1. **注重质量的开发者**：追求高质量软件交付的工程师。
2. **问题解决者**：对攻克复杂软件问题感兴趣的人。
3. **MySQL 爱好者**：希望自下而上理解 MySQL 的读者。
4. **测试从业者**：希望掌握更有效性能测试方法的用户。
5. **软件架构师**：需要设计大规模系统的架构人员。
6. **性能工程师**：长期与性能优化打交道的工程师。
7. **计算机专业学生**：希望夯实基础的学习者。
8. **MySQL 研究者**：以 MySQL 为对象开展研究的人员。

## 本书大纲

第 1 部分集中讨论与 MySQL 相关的问题。第 1 章梳理用户通常如何应对疑难问题；第 2 章聚焦 MySQL 8.0 中的若干“反常”现象。

第 2 部分介绍排障所需的基础知识。第 3 章强调逻辑推理的作用；第 4 章补充与 MySQL 问题相关的计算机基础；第 5 章介绍内核要点，为后文分析做准备；第 6 章讨论科学的测试方法。

第 3 部分进入具体问题的分析与改进。第 7 章概括 MySQL 8.0 的重要优化；第 8 章讨论面向 8.0 特定问题的改进；第 9 章讲述组复制增强；第 10 章讨论从库回放改进。这些内容既提升性能，也为高可用集群打下基础。

第 4 部分从用户视角讨论性能提升。第 11 章介绍在不改业务代码的前提下改善 MySQL 8.0 应用性能的方法。

第 5 部分为总结。第 12 章展望后续方向并收束全书。

## 特殊术语说明

1. **平衡回放速度**

   对 MySQL 从库回放而言，平衡回放速度指：在正常条件下，从库能够跟上主库的那一速度阈值。主库速度不超过该阈值时，从库事务回放基本无明显落后；一旦超过，从库回放进度就会开始落后于主库。

2. **双一**

   特指 MySQL 的两项关键配置：*sync_binlog=1* 与 *innodb_flush_log_at_trx_commit=1*。

3. **MySQL 从库回放**

   泛指异步复制、半同步复制与组复制中共通的回放过程。本书统一用“MySQL 主库”指 source，用“MySQL 从库”指 replica。

## 部署补充说明

测试部署应尽量贴近生产环境，除非某些配置会严重干扰性能分析。本书测试相关约定如下：

1. 所用主流服务器多为 4 路 NUMA 架构。
2. 服务器一般采用 x86 架构。
3. 使用 NVMe SSD，I/O 延迟很低。
4. 测试均在高性能服务器上进行，结果仅代表该类配置。
5. 测试操作系统为 Linux。
6. 单机测试通常基于 MySQL 8.0.27，集群测试通常基于 8.0.32。
7. 文中对 MySQL 的改动版本称为“改进的 MySQL”或“修改的 MySQL”。
8. TPC-C 测试的事务隔离级别为 *Read Committed*。
9. 事务存储引擎为 InnoDB。
10. 除非另有说明，组复制测试默认使用单主模式。
11. *binlog_format* 使用基于行的格式。
12. 主库与从库均启用 GTID（全局事务标识符）。
13. 集群配置包含 *replica_preserve_commit_order=on*。
14. 多数测试基于 BenchmarkSQL TPC-C。
15. 除非另有说明，TPC-C 一般基于分区大表。
16. 软硬件与配置细节见附录。
