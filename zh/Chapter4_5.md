# 4.5 编译器理论

编译器理论覆盖语言与文法、词法/语法分析、语法制导翻译、中间代码、存储分配、代码优化与目标代码生成等。其中，有限状态机（FSM）是贯穿始终的核心工具。

## 4.5.1 有限状态机

FSM 用有限状态、迁移与动作描述系统行为，广泛用于编译器、网络协议、游戏引擎等：既能刻画算法流程，也能响应事件。

在 MySQL 里，FSM 出现在词法/语法分析，以及组复制控制中。例如组复制在 Paxos 处理时，会依据状态决定继续推进，还是在内存分配失败时报错退出；某状态无法继续时退出并报错，有助于避免拜占庭式异常。

TCP/IP 里也用状态机识别异常，例如服务端大量 *CLOSE_WAIT*，往往意味着连接未正确关闭。

## 4.5.2 MySQL 解析器

MySQL 解析器基于 C/C++，用 Flex 做词法、Bison 做语法，把 SQL 解析为内部结构。代理做读写路由、把 SQL 变成语法树等，都依赖解析。

随着 CPU 核数增加，解析本身占整体 CPU 的比例下降，这也部分解释了为何 8.0 去掉查询缓存。

## 4.5.3 PGO

配置文件引导优化（PGO）用插桩运行收集的 profile 指导编译优化，减少对程序员手填频率信息与启发式的依赖；只要 profile 代表典型负载，就可能明显提速。

MySQL 代码体量大，很适合 PGO，但收益受 I/O 与网络牵制：慢盘场景下 I/O 成主瓶颈，按阿姆达尔定律，PGO 增益有限；NVMe 等快存储上更易看到收益。网络延迟升高通常也会削弱效果。
