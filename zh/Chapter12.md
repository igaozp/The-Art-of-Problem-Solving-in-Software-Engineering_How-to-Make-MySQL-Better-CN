# 第 12 章：未来方向

扎实基础是走向更高目标的前提。在可扩展性与高可用问题得到较好解决之后，可以重点关注以下方向。

## 12.1 超图算法的改进

目标是让超图算法真正可用，并提升其性能，尤其值得探索并行化路径。

## 12.2 Paxos 日志持久化的工程落地

目前已证明 Paxos 日志持久化可行。下一步应实现基于该日志的崩溃恢复，使其具备生产可用性。

## 12.3 解决并发视图变更难题

组复制仍存在棘手的并发视图变更问题。虽出现频率不高，仍值得彻底解决。

## 12.4 继续提升可扩展性

可在以下方面继续推进：

1. 消除额外锁存器瓶颈，尤其在非分区环境中。
2. 提高长时间性能测试的稳定性。
3. 在主流 NUMA 环境中增强 MySQL 的 NUMA 感知。
4. 解决 Performance Schema 在从库回放路径上对 NUMA 环境的不利影响。

## 12.5 继续改善低并发 SQL 性能

相对 5.7，MySQL 8.0 在低并发下往往更慢，需要纠正，以免影响升级意愿。

## 12.6 增强分析型 SQL 性能

当前单条 SQL 多为单线程执行，部分统计类查询耗时过长，影响体验。未来可面向统计查询引入多线程执行，缩短耗时。

## 12.7 提高 Binlog 压缩效率与运行稳定性

降低存储成本是重要目标。优化 binlog 压缩率与稳定性，仍有较大改进空间。

## 12.8 改进主库对大事务的处理

在主流 NUMA 环境下，主库处理大事务效率仍不理想，优化空间明显，可能成为后续重点之一。

## 12.9 探索更好的内存分配器

目前 jemalloc 4.5 综合表现最好，但在 ARM 上存在内存占用偏高、不够稳定等问题。更高效、更稳的分配器仍值得投入。

## 12.10 集成高性能文件系统

为 MySQL 引入更合适的文件系统，尤其有望提升从库回放性能。

## 12.11 将 AI 引入 MySQL

把 AI 用于自动参数调优与基于学习的监控，可能是另一个重要方向。

### 12.11.1 参数调优

用 AI 做参数优化可明显减轻 DBA 负担。较适合的参数包括：

1. 缓冲池大小
2. 自旋延迟
3. 按环境动态调整的事务节流上限
4. 动态 XCom 缓存大小
5. 从库 worker 最大队列长度
6. Paxos 流水线实例数与批大小
7. 高负载下自动调参以提升处理能力

### 12.11.2 基于学习的数据库监控

AI 还可帮助决定：在何时、以何种方式跟踪各类数据库指标，使监控更有效。

## 12.12 总结

编程依赖扎实的逻辑推理：它贯穿问题分析、算法设计、调试、代码理解、性能优化与测试，帮助拆解问题、构造方案、修正错误并保障可靠性。培养逻辑推理，是程序员系统性思考、构建高效可靠软件的基础 [56]。

MySQL 开发若只依赖测试工具做简单压测，容易漏掉大量问题。测试 MySQL 本身就很难，工具覆盖有限；不同项目与环境差异很大，结合真实在线流量做优化往往更有针对性。因此，基于实时流量的优化很有价值。

性能优化很大程度上取决于可扩展性瓶颈是否被缓解。增强版 MySQL 已解决大部分可扩展性问题，为后续优化打下基础。PGO 的价值会随着可扩展性改善进一步放大；更好的内存分配器也能同时惠及主库与从库回放。

我们相信，基于 Paxos 日志持久化的高可用方案会是重要趋势。在组复制长期演进上的经验，有助于走向真正可用的高可用。从库回放速度直接决定高可用质量；回放达到百万级 tpmC 是可能的，但需要持续投入。

MySQL 优化路长且曲折，但我们相信它会随时间不断变好。
